Did we test it end to end?

Yes for the core product, in one browser. Not on real devices or with real services.

"Tested" here means a real click or a Playwright step against a running app, with no stubs. That rule came from the End Session bug, which earlier testing had hidden.

Tested

  • Host flow: build a deck, present, open the lobby, phones join, answer, reveal, end, open the reportBy hand in the browser pane and in Playwright

  • Sign up, verify the email, log in, reset the password, stay signed in, log outPlaywright
  • Quick polls: build, draft, publish, vote anonymously and with a name, one vote per person, close, publish resultsPlaywright

Found and fixed today · 18

What the test pass caught

All fixed and committed. The new end-to-end tests now guard each one.

Data or security

5
  • A wrong password could sign in another sessionThe token-refresh logic ran on a failed login.
  • One email could vote twice on a named pollTyping a different name counted as a new person.
  • Assessment retries could be resetSame loophole: a new name gave fresh attempts.
  • Unsaved deck edits were lost on reloadThe saved copy overwrote the newer local draft.
  • Builder and host pages opened while signed outThey are now behind the login.

Broken in real use

7
  • End Session and Close lobby did nothingIn embedded browsers, like the Claude app pane, the native confirm box answered "no".
  • Three settings buttons had the same problemRemove domain, revoke SCIM token, delete SSO connection.
  • The tests auto-accepted those boxesThat is why CI was green. They now fail if a native box appears.
  • The audience join page used up the login rate limitOn shared conference Wi-Fi this caused "too many requests" errors.
  • A lost session showed a page of errorsIt now goes to the login page.
  • A short join code did nothingNow it says to enter the 6-digit code.
  • An imported deck opened with an empty titleA regression from the reload fix, caught by the tests the same day.
