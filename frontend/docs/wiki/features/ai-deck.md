# AI whole-deck authoring (`features/ai/deck/`)

Backend contract: `backend/docs/wiki/modules/ai.md` ("Whole-deck authoring",
`POST /api/ai/generate-deck`). The deck is created by the API in the caller's workspace (the
`X-Workspace-Id` header comes from `apiClient`), as a draft with speaker notes on every slide.

## Entry point

The builder's **AI generate** button (and `?mode=ai` from the "New Presentation Deck" modal) opens
`features/presentations/components/AiPresentationModal.tsx`. It has two tabs:

- **Whole deck** (default for a new deck; `isEditing` makes **Quick slides** the default): renders
  `AiDeckPanel`. The dialog is wider and cannot be dismissed while slides are being written.
- **Quick slides**: the original generator (`POST /api/ai/generate-quiz`, questions merged into the
  deck being edited). Unchanged.

## Flow (`state.ts` reducer, `flow.ts` async steps, `useAiDeck.ts`)

`form -> planning -> outline -> writing -> done`

| Phase | Component | What happens |
| --- | --- | --- |
| form | `AiDeckForm` | Topic (seeded from the deck name), audience, language, slide count 3-30, tone, include switches (content / polls / quiz, at least one), optional source text (<= 20,000 chars, collapsed). Validated client-side like the backend (`form.ts`); errors show after the first submit. If `capabilities.ai` is false a note says the deck will be built from placeholders. |
| planning | `AiDeckPlanning` | `step: "outline"` request (cancellable: aborts the request; nothing is stored). The deck name, if any, is sent as `title`. |
| outline | `AiDeckOutline` | Edit the deck title, section titles, slide intent and type (select from `availableKinds`), reorder (moves cross section edges), remove, add. `outline.ts` has the pure edits and `validateOutline` (title, section titles, intents, 1-30 slides). A failed write returns here with the error. |
| writing | `AiDeckWriting` | `step: "deck"` request with the cleaned, reviewed outline (`cleanOutline`); elapsed seconds; not cancellable (the server finishes the deck either way). |
| done | `AiDeckResult` | Source label, warnings, the slides with their first lines of speaker notes, plan usage; **Open in builder** or **Generate another**. |

Errors (`api.ts` `toDeckError`, `AiDeckError`): plan limit (403 `PLAN_LIMIT_REACHED`, shows the
plan maximum), rate limit (429), provider failure / empty deck (502), forbidden, invalid, network.

## Mock mode is always labelled

When the server answers `source: "mock"` (no AI key; `capabilities.ai === false`):

1. the form says so before anything is sent (`ai-deck-mock-capability`);
2. the outline step and the result step show `MockDataNotice`: **"Generated with mock data (no AI
   key configured)"** (`data-testid="ai-deck-mock-notice"`);
3. the builder shows the same notice as a dismissible banner (`AiDeckBanner`) while the URL has
   `?aiSource=mock` (`source.ts`), because the slides and notes are placeholders.

A real model result shows "Generated by AI. Check the facts before you present." and no banner.

## Hand-over to the builder

`AiPresentationModal` calls `onDeckCreated({presentation, source})`;
`useDeckBuilder().handleDeckCreated(deck, source)` shows the created deck in place: sets title and
slides, `skipNextLoadIdRef` (no refetch), `draftStateRef.editId` (later saves target the new
deck), clears the "new deck" local draft only when it was empty, and `router.replace`s to
`/presentation/create?id=<id>[&aiSource=mock]` (`builderParamsAfterGeneration`). Work in progress on
the previous deck stays in its local draft.

The builder has no speaker-notes editor yet (W2-A adds `builder/NotesTab.tsx`); notes survive
builder saves because every slide editor spreads the slide it cleans. The result step lists them.

## i18n

Strings live in `messages/en/ai.json` (namespace `ai`, registered in `i18n/messages.ts`). The
builder sits outside the live intl provider, so `AiIntlProvider` supplies the `ai` namespace to
`AiDeckPanel` and `AiDeckBanner`. Deck kinds without a label (`kinds.ts`) fall back to a humanized
key, so a kind the backend adds later still shows.
