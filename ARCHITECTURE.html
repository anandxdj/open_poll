📊 Polls

Passive, form-style surveys. Creator publishes; respondents fill async. Real-time analytics via buffered Redis → MongoDB writes. Device-based dedup. Guest email gate on non-anonymous polls.

Async responses Expiry-based lifecycle Analytics worker

Synchronous, host-driven sessions. Live competition with scoring, timers, leaderboards. Redis hot path for answer submissions. 6 slide types: 2 scored + 4 interactive.

Gemini 2.0 Flash with LangGraph StateGraph. Generates full poll/quiz drafts from topic + config. Repair pass coerces LLM output to valid schema. Mock fallback if API unavailable.

🎮 Quiz Architecture

Slide Types

SCORED

select_answer

Multiple choice. Options with isCorrect flag. Points + time multiplier. Distribution: option counts.

SCORED

type_answer

Free text matching acceptedAnswers[]. Normalized (lowercase + collapse spaces). Top 20 shown on reveal.

INTERACTIVE

wordcloud

Up to 3 entries per participant. Dedup via original-casing hash. Top 100 on reveal. Variable font size by frequency.

INTERACTIVE

open_ended

Free text, 500 char max. Top 50 responses shown as card grid. No scoring.

INTERACTIVE

scales

2–5 statements, each rated 1–N. Average + response count per statement shown as horizontal bars.

INTERACTIVE

ranking

Drag-to-reorder items. Borda count aggregation (top = N pts, last = 1 pt). Final rank displayed as bars.

Data Model

Quiz Document

interface IQuiz {
  creatorId:         string
  title:             string
  joinCode:          string   // 6-digit unique, 5 retry on collision
  status:            'draft' | 'lobby' | 'question'
                   | 'reveal' | 'leaderboard' | 'ended'
  currentSlideIndex: number   // -1 before first question
  questionStartedAt: Date | null
  questionEndsAt:    Date | null
  slides:            IQuizSlide[]
}

interface IQuizSlide {
  type:              SlideType
  question:          string
  options:           { text: string, isCorrect: boolean }[]
  acceptedAnswers:   string[]
  statements:        string[]
  minLabel:          string
  maxLabel:          string
  scaleMax:          number    // 2-10
  items:             string[]
  maxEntries:        number    // wordcloud: 1-3
  timeLimit:         number    // seconds, 5-300
  points:            number    // 0-10000
  scoreDependsOnTime: boolean
}

Participant Document

interface IQuizParticipant {
  quizId:       ObjectId
  name:         string   // max 30 chars
  deviceId:     string   // unique per quiz (compound index)
  token:        string   // 24-byte hex, issued once on join
  score:        number
  correctCount: number
  joinedAt:     Date
}

Answer Document

interface IQuizAnswer {
  quizId:        ObjectId
  participantId: ObjectId
  slideIndex:    number
  optionIndex?:  number     // select_answer
  text?:         string     // type_answer, open_ended
  payload?: {
    entries?:  string[]    // wordcloud
    ratings?:  number[]    // scales
    ranking?:  number[]    // ranking (indices)
  }
  isCorrect:     boolean
  score:         number
  timeMs:        number    // server-side elapsed (anti-cheat)
}

Scoring Formula

score = points × (1 − elapsed / timeLimit / 2)

Fastest correct answer = full points. Slowest correct answer = 50% points. Wrong = 0. Non-scored slide types always = 0 regardless of setting. Grace window: 750ms after timer for network latency.

Content Sanitization

⚠️
Anti-cheat: When broadcasting question:started, the slide is sanitized — isCorrect flags and acceptedAnswers[] are stripped. Participant state endpoint only returns lastAnswer after status transitions to reveal, leaderboard, or ended. Server-side timing (stored in Redis LiveSession) means clients cannot fake faster responses.

Participant Join — Idempotent Flow

POST /quizzes/:id/join { name, deviceId }

1. Find quiz by id, verify status !== 'ended'
2. QuizParticipant.findOne({ quizId, deviceId })
   → EXISTS:  Return existing participantId + fresh token view
   → MISSING: Insert new participant, generate token (24-byte hex)
3. Cache in Redis: quiz:{id}:tokens HSET participantId → token
                   quiz:{id}:names  HSET participantId → name
4. Publish 'participant:joined' event to all in room
5. Return { participantId, token }   ← token ONLY shown at join, never broadcast

🔴 Redis Key Catalog

Quiz Keys (TTL: 6h after last state change)

quiz:{quizId}:session
STRING (JSON) — Hot path
LiveSession: slideIndex, timing, slide type/config, answer validation data. Pre-computed to avoid Mongo reads on answer path.
quiz:{quizId}:scores
ZSET — Score leaderboard
participantId → cumulative score. ZINCRBY on each correct answer. ZREVRANGE for leaderboard display.
quiz:{quizId}:correct
HASH
participantId → correct answer count. Incremented alongside scores.
quiz:{quizId}:names
HASH
participantId → display name. Used in leaderboard without Mongo lookup.
quiz:{quizId}:tokens
HASH
participantId → secret token. Verified on every answer submission.
quiz:{quizId}:answered:{slideIndex}
SET — Dedup
participantIds who answered this slide. SADD returns 0 on duplicate → reject. One per slide.
quiz:{quizId}:dist:{slideIndex}
HASH — Distribution
option/text/normalized → count. Used on reveal to compute distribution per slide type.
quiz:{quizId}:disp:{slideIndex}
HASH — Display casing
normalized → first-seen original casing. Word clouds show "JavaScript" not "javascript".
quiz:{quizId}:results:{slideIndex}
HASH — Per-participant
participantId → { isCorrect, score, scored }. Served on getParticipantState after reveal.

Poll Keys

poll:{pollId}:voted:{deviceId}
STRING — 24h TTL
Vote dedup marker. Set on submit; reject duplicate device within 24h.
buffer:active_polls
SET
Polls with pending analytics buffer. Worker pops from this set every 2s.
buffer:poll:{pollId}:total
STRING (counter)
Accumulated response count delta since last flush.
buffer:poll:{pollId}:question:{qId}
HASH
optionIndex → accumulated count delta for this question.
poll:{pollId}:analytics_cache
STRING (JSON) — 1h TTL
Cached analytics result. Cleared on each worker flush, rebuilt on next read.

🎯 Mentimeter Feature Gap Analysis

📋
Mentimeter is the leading interactive presentation platform. Below are features they have that we're missing — categorized by impact and effort. Mentimeter treats quizzes as one slide type within a broader "presentation" metaphor.

Critical Missing Features (User Retention Risk)

🔴 Post-Session Results Page

After quiz ends, all data lives only in Redis (6h TTL). No permanent results page creator can share or revisit. Mentimeter keeps all results indefinitely with shareable link.

P0  Backend: persist to Mongo on end. Frontend: results viewer route.

🔴 Anonymous Participant Mode

Quizzes always require a nickname. Mentimeter supports fully anonymous answering. Some audiences (corporate, sensitive topics) need this.

P0  Add isAnonymous flag to quiz. Skip name gate in PlayView.

🔴 Audience-Paced Mode

Mentimeter's default is audience-paced (all questions visible at once, respond at own pace). We only have host-paced. Major use case for surveys and onboarding quizzes.

P0  Significant: needs new session model (no state machine).

🟡 Results Export (CSV/PDF)

Mentimeter allows downloading full response data as CSV or PDF slide deck. Critical for post-event analysis.

P1  Backend CSV endpoint. Frontend download button in results view.

🟡 Q&A / Back-Channel

Mentimeter has a dedicated Q&A slide type where audience submits questions, host moderates (upvote, archive, mark as answered). Huge for conferences.

P1  New slide type + moderation UI for host.

🟡 Image/Media in Slides

Mentimeter supports images in questions and option buttons. Visual context dramatically improves engagement for content-rich quizzes.

P1  File upload (S3/Cloudflare R2), image field on slide schema.

High-Value Missing Features

🔵 Email Capture at Join

Polls have guest email gate; quizzes don't. Conference lead-gen use case: capture attendee emails during interactive sessions.

P2  Optional email field on join. Exportable with results.

🔵 "Pin on Image" Slide Type

Participants click on an image to indicate their answer (heat map). Used for product feedback, geography questions, diagrams.

P2  New slide type. Complex: coordinate storage + heat map viz.

🔵 Emoji / Quick Reactions

Mentimeter has live emoji reactions participants can send during any slide. Increases engagement, not tied to scoring.

P2  Socket event. No Mongo write needed. Frontend floating emojis.

🔵 Custom Branding / Themes

Mentimeter Pro: custom colors, logo, font. Corporate clients expect white-label presentation experience.

P2  Theme schema on Quiz. CSS variables injected per quiz.

🔵 "Guess the Number" Slide

Participants enter a number; results show guesses on a number line. Close-is-correct scoring variant.

P2  New slide type. Median + histogram visualization.

🔵 Speaker Notes

Host can add notes per slide visible only in host view. Essential for scripted presentations.

P2  Add hostNotes field to slide schema. Display in HostView.

🔵 Voting Limits / Pace Control

Mentimeter allows multiple votes per participant, vote weighting, and pace locking (participants can't advance). We have single-vote only.

P2  Remove SADD dedup gate (or make configurable).

🔵 Presentation Template Library

Mentimeter has 300+ pre-built templates by use case (icebreaker, retrospective, training). Dramatically lowers barrier to first quiz.

P2  Seed DB with templates. Template picker in create flow.

Nice-to-Have / Future Differentiators

⬜ PowerPoint / Google Slides Plugin

Mentimeter has Office add-in + Google Slides extension. Present from existing decks with live polls embedded.

P3  Separate product track. iFrame embed is prerequisite.

⬜ Hand Raise / Queue

Participants raise a virtual hand; host sees queue. Used in webinars and classrooms.

P3  Socket event. Host moderation UI.

⬜ Teams / Collaboration

Multiple creators on one workspace. Shared quiz library. Mentimeter Teams plan.

P3  Auth overhaul. Org/team data model.

⬜ LMS Integration

Google Classroom, Canvas, Blackboard integration. Grades sync. Education market.

P3  OAuth flows per LMS. Standards: LTI 1.3.

⬜ Password Protection

Join code + password for private sessions. Mentimeter supports this on Pro.

P3  Add joinPassword field. Check at join endpoint.
